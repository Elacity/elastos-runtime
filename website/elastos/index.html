How it fits together

What ElastOS is

Your hardware is the root of trust. The chain is the registry for tradable, ledger-limited rights.

01 /

Runtime

The software that runs on your machine. It manages apps, services and access to your data.

02 /

Home

Your desktop in the browser. Sign in with a passkey to open apps and manage your account.

03 /

Apps

Web apps for tasks such as writing, managing files and connecting with people. A source package becomes a signed capsule only after complete packaging and signing. Your documents and settings stay separate from the installed app.

04 /

Permissions

Reading a document, changing it and sharing it each need permission. Runtime checks access for apps and AI agents alike.

Current boundary

Isolation status

This describes the current source boundary. Apps run as web projections in the browser's opaque sandboxed frames. Runtime checks each app's signed launch token and actor before it performs an effect. Home can currently obtain every app's capability. The target limits Home to delegation and gives each app a separate, revocable capability. WASM Components use a separate authoring path with Wasmtime memory and fuel limits and Runtime Bus hostcalls.

Providers

Providers run as operating-system processes with the Runtime user's rights. Only the model provider is partly confined. The trusted shell helper runs as a native host process. The web Terminal is disabled by default and requires host developer mode and closed guest registration. An enabled Terminal runs commands as the host user.

Data and keys

Keys are stored next to the data they protect. Full backups contain all keys. The seed operator can read data, wallet keys and recovery phrases stored on the seed. Use hosted accounts only for public demos; keep wallets, private data and recovery material on your own device until hosted protection passes its acceptance gate.

Sign-in and recovery

Passkeys control sign-in. The Runtime account and root can read stored data and keys while Home is locked. The target protects against hosted operators and root, and other software or OS users while a self-hosted Home is locked. An unlocked self-hosted Home trusts its owner and their host software. Recovery from a stolen device or profile key requires a new identity. Keep your Recovery Kit under your own control.

Proof

The content sandbox, front-door and disabled-terminal paths must be integrated and tested together on each accepted installation. Accepted installed proof binds the exact Runtime, components and app assets to tested journeys on that device.
