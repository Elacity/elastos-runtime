# Read order

Law first. Then the map. Then the contract for the layer you are touching. Then known issues. Then `state.md`.

1. `PRINCIPLES.md` in the repo. That file wins.
2. `principles.md` here. The teaching cut. If it fights the repo file, the repo file wins.
3. `tree-map.md`. Where the code lives.
4. `glossary.md`. Lookup. Not law.
5. The contract for your layer: `carrier.md`, `capsules.md`, `providers.md`, or the repo files they point at (`docs/CARRIER.md`, `docs/CAPSULE_MODEL.md`, `docs/ESP_V0.md`, `docs/HOME_SHELL_HOST_CONTRACT.md`).
6. `agent-gates.md` before you edit.
7. `known-issues.md` before you call something done.
8. Repo `state.md` and `TASKS.md` for what is actually shipped.

If a diagram fights Principles, the diagram is wrong. The gossip drawing in `docs/CARRIER.md` is the usual trap.
