# Marketplace in the Runtime — review artifacts

Branch `feat/marketplace-runtime` (off the dDRM line; merge back when green). Contains the browser-verified UI shell, the turnkey specs/contracts, and **compile-verified backend Rust** being built crate-by-crate (e.g. `trade_authority`). Workflow: Claude builds + compile/unit-test-verifies; **Cursor does live-chain integration testing + sign-off** (the money-path can't be live-tested here — no funded wallet/test Operative/dKMS backend); the human holds the merge.

> **Scope (canonical): [SCOPE.md](SCOPE.md).** The marketplace is a **buy/trade venue for all dDRM assets** — it mints nothing (creator app) and plays nothing (runtime players); on buy the encrypted file pins to your Library and opens in the existing player. PLAN.md/layouts.html predate this correction.

- **[ROADMAP.md](ROADMAP.md)** — branch status + the lifecycle matrix (buy·trade·list·withdraw, UI done / backend specced) + the build order for Cursor. **Start here.**
- **[PLAN.md](PLAN.md)** — the full plan: verdict, architecture (reuse vs rewrite), capsule structure, data model, trade model, UX/IA, honest scrutiny (PC2 vs elacity-web vs runtime-native), the money-path-first phased path, the council, and the evidence caveats.
- **[PHASE1_BUY_INVARIANT.md](PHASE1_BUY_INVARIANT.md)** — the #1 build item and the gate for everything: bind buy terms to the re-verified on-chain listing + abort-on-drift (fixes the env-pinned / `content_id`-derived `tokenId` landmine that would let a buy debit the wallet and grant no access). **No buy UI ships until this passes.**
- **[PHASE2_INDEX_AND_API.md](PHASE2_INDEX_AND_API.md)** — the discovery layer: `content-index` (a polling cache table behind the gateway, *not* a capsule, fed by `content-market` over `chain-provider`) + the `/api/market/*` gateway routes the shell already consumes. Includes the listing schema, the getLogs poll loop (cursors/backfill/reorg/SLO), and the live re-verify-at-point-of-use rule.
- **[CONTRACTS.md](CONTRACTS.md)** — the turnkey **smart-contract reference** (Base mainnet): every selector/event/address for buy·list·cancel·has-access, the AuthorityGateway/TradeGateway/Operative role model, and the per-verb mapping to the runtime seams. All 20 selectors keccak-recomputed; **read its "Verification status"** — buy-path core is in-tree-confirmed, secondary-market selectors + non-gateway addresses are to-verify-against-bytecode.
- **`../../capsules/marketplace-content/`** — the runnable, browser-verified shell capsule (open `browser/index.html`): Discover · Asset-detail · Buy (unsigned→wallet, then pins to Library) · Trade/Resale · Withdraw · Vault, asset-type aware. Holds no authority; **mints nothing, plays nothing**; `browser/api.js` is the source-of-truth for the `/api/market/*` contract.
- **[layouts.html](layouts.html)** — an early self-contained visual mock. ⚠️ **SCOPE-superseded** (it shows a "Studio" nav + an in-app "secure stage" — both removed). The runnable, browser-verified shell + [SCOPE.md](SCOPE.md) govern; the asset detail is a passive **poster/cover**, not a secure-render stage.

One-line essence: the runtime already has the trust spine (`content-market` decode + the dDRM open path); the work is a polling listing-index (cache, not capsule), a marketplace shell capsule (porting elacity-web UX *behavior*), and — first, before any buy button — making a purchase provably grant the access it charges for.
