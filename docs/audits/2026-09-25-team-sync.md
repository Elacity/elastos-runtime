# ElastOS weekly report, 19-25 September 2026

The public Home can now install its signed SmolLM2 capsule and use it in Assistant. That was the main failure at the end of [last week's report](2026-09-18-team-sync.md). This week's tests also proved a model transfer to a fresh Mac Home and one approved model share between two separate Homes. Each result belongs to the build and Home named in its receipt; the public seed still runs a smaller, separately approved patch.

| Area | What changed | Still open |
| --- | --- | --- |
| Local models | The public seed completed Marketplace Get, one short SmolLM2 reply, restart and reuse. A fresh Mac Home received the full signed package from another holder. Source fixes make Get → Use work without a restart, clear stale activation status and keep long downloads showing progress. Earlier Mac checks also recorded a real Qwen3.5-9B reply, save, reload and restart. | SmolLM2-135M proves the installation path and a short reply. The release still needs a useful local Assistant: a measured model on the seed and the signed Qwen3.5-9B journey on a suitable Mac. Qwen3.5-4B is the first seed candidate, subject to engine, signing, answer-quality and resource checks. The seed already held SmolLM2 before its Get, so fresh network delivery there remains unproven. |

PR62 adds another external-data consent path; it needs to use the same Runtime authority as hosted AI. The contributor work is not integrated into a release candidate. |

Model-process isolation is the largest release gate. The public seed's local model process does not yet have Linux containment. The current installed Mac model process has more access to user files than the capsule contract allows. Controlled tests have advanced hosted consent and child isolation, but the installed paths remain open. We need a reviewed Linux containment plan for the seed, then installed Mac and Linux proof of the ordinary Inbox approval and End journey.

The focused [0.7.2 plan](https://app.notion.com/p/3d6b682adcca81948f78d12abcd677b9) is a usable public Home with local and approved hosted Assistant, Community Chat, a local Mac Browser, and an update path that preserves user state. The wider Qwen distribution and benchmark matrix, remote model sharing, remote Browser placement, protected purchases, Linux ARM64 delivery and relay qualification remain later work. The model source is in [draft PR #71](https://github.com/Elacity/elastos-runtime/pull/71), stacked on [PR #64](https://github.com/Elacity/elastos-runtime/pull/64). The approved seed preview has separate [Runtime source](https://github.com/Elacity/elastos-runtime/tree/deploy/0.7.1-seed-runtime) and [Home UI](https://github.com/Elacity/elastos-runtime/tree/deploy/0.7.1-seed-home-ui) branches. These branches document current work; the 0.7.2 release is still open.

After the initial report, PR #71 failed its UI source checks in CI. A separate [fix at `3d51690c`](https://github.com/Elacity/elastos-runtime/commit/3d51690c975964f5386aadd2009ee67b043f1fe6) pins Node 26, the version used by the passing local checks. The fix is published on `fix/0.7.2-model-ci-node`; integration into PR #71 and a passing GitHub run remain open. The [earlier Qwen receipt](https://github.com/Elacity/elastos-runtime/blob/f200dde1992cbb08e707faea2f2171773d837387/docs/audits/2026-09-11-assistant-convergence.md) remains evidence for its tested Mac build.

Before a release candidate, we need decisions on how Chat ships, which Linux containment method protects model providers, which model the seed should offer for regular use, who holds signing keys, who restarts Home after an update, and which public-seed accounts may configure and pay for hosted AI. Those choices belong in the plan before the final installed checks.
