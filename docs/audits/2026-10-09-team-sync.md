# ElastOS weekly report, 2 - 9 October 2026

Signed updates now work on real machines. Twelve signed test releases (0.8.0-alpha.1 to alpha.12) went out with the new release key, and updates, Undo and recovery were tested on a Mac, a Linux PC and the Jetson. ## CI, CD and builds

CI ran 292 times this week. From 3 to 6 October it ran between 39 and 72 times a day, and fewer than half the runs passed. From 7 October reviewed branches went into one train PR per test release, each train was checked once in full before the push, and it got one CI run. Runs dropped to 12 to 25 a day, and two thirds or more passed.

What changed ([#194](https://github.com/Elacity/elastos-runtime/issues/194)):

- Every PR opens an installed Home, signs up and sees the update in System ([#240](https://github.com/Elacity/elastos-runtime/pull/240)). On Mac it also updates from a real earlier release and then Undoes ([#259](https://github.com/Elacity/elastos-runtime/pull/259)).
- On Mac, Linux and ARM, CI installs Home, gets a model from Marketplace and checks that Assistant replies (#153, merged through #306).
- Behaviour test suites and local pre-push checks ([#224](https://github.com/Elacity/elastos-runtime/pull/224)), lint for every app ([#251](https://github.com/Elacity/elastos-runtime/pull/251)), fewer rebuilds in the pre-push gate ([#263](https://github.com/Elacity/elastos-runtime/pull/263)), and flaky tests made deterministic ([#273](https://github.com/Elacity/elastos-runtime/pull/273)).
- Kubo and system packages come from a verified cache ([#268](https://github.com/Elacity/elastos-runtime/pull/268)). Before this, Kubo download timeouts had failed 53 jobs in a week.
- Only sources with green `develop` CI can be published ([#267](https://github.com/Elacity/elastos-runtime/pull/267)).
- A PR run stops at its first failed job, and package installs retry.
- Release builds are hermetic and use no CI caches; one release workflow builds every platform without a key ([#241](https://github.com/Elacity/elastos-runtime/pull/241), [#247](https://github.com/Elacity/elastos-runtime/pull/247), [#299](https://github.com/Elacity/elastos-runtime/pull/299)).

A full run takes 50 to 80 minutes, up from 32 last week. Part of that is the new installed-Home journeys; part is that the shared compiler cache stores nothing, so every job compiles about 1,800 crates from scratch, as Irzhy found ([#310](https://github.com/Elacity/elastos-runtime/issues/310)). Fixing the cache is the next CI job. The merge queue stays off: my measurement on 8 October showed it costs more CI time than it saves when each PR is pushed once.

Checks before a push run on rented Linux machines (76 runs from 6 to 9 October, plus 55 turned away because another check was running). Pushes go through a queue that runs the pre-push gate one branch at a time (50 attempts, 36 passed). Real-machine tests use scripts that install a release on a fresh Linux machine or the Jetson and run update, Undo, an interrupted update, low disk or the AI journey (70 runs from 6 to 9 October).

Eight of his issues are in the 0.8.0 milestone; Apple notarization (#316) and the full Rust workspace checks (#318) come after.

## How we work now

- One release, five goals in order, weekly signed test releases, two milestones: 0.8.0 and After 0.8.0.
- After the first signed install, everything comes from inside ElastOS; only the release build fetches outside software, from checksum-pinned recipes ([#217](https://github.com/Elacity/elastos-runtime/issues/217)).
- Status lives in issue bodies, edited in place, not in the repository or in comment threads.
- Each fix gets fast checks and a review from a different AI model family. Each batch gets one full check and one CI run, and only failed jobs are rerun. Nobody starts CI by hand just to get build files.
- I run releases, CI, the seed and Local AI; Codex runs the Browser and Chat. Important plans and replies to teammates get a devil's-advocate check first.
- When the shared Mac's disk dropped below 10 percent free and blocked builds, old release folders and finished worktrees were deleted; it now has more than 80 GB free.
