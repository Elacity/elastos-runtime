# ElastOS weekly report, 3 - 9 October 2026

This was the week signed updates started working on real machines. Twelve signed test releases (0.8.0-alpha.1 to alpha.12) went out with the new release key, and most of them were installed or updated on a Mac, a Linux PC or the Jetson. Local AI now downloads a model over the network and answers on the device, on Linux and the Jetson. Chat came together in one pull request. The Browser design is settled but nothing is proven on a fresh install yet. On 7 October we stopped making weekly 0.7.x versions and planned one 0.8.0 release with five goals. Last week: [26 September - 2 October](https://github.com/Elacity/elastos-runtime/blob/docs/weekly-2026-10-02/docs/audits/2026-10-02-team-sync.md).

## CI, CD and builds

CI ran 292 times this week. From 3 to 6 October it ran between 39 and 72 times a day, and fewer than half the runs passed. From 7 October work went through trains: reviewed branches are batched into one PR per test release, checked once in full before the push, and get one CI run. Runs dropped to 12 to 25 a day, and two thirds or more passed.

What changed in CI ([#194](https://github.com/Elacity/elastos-runtime/issues/194)):

- Every PR now opens an installed Home, signs up and sees the update in System ([#240](https://github.com/Elacity/elastos-runtime/pull/240)), and on Mac it updates from a real earlier release and then Undoes ([#259](https://github.com/Elacity/elastos-runtime/pull/259)).
- On Mac, Linux and ARM, CI installs Home, gets a model from Marketplace and checks that Assistant replies (#153, merged through #306).
- Behaviour test suites and local pre-push checks ([#224](https://github.com/Elacity/elastos-runtime/pull/224)), lint for every app ([#251](https://github.com/Elacity/elastos-runtime/pull/251)), and flaky tests made deterministic ([#273](https://github.com/Elacity/elastos-runtime/pull/273)).
- Kubo and package downloads come from a verified cache ([#268](https://github.com/Elacity/elastos-runtime/pull/268)). Before this, Kubo download timeouts had failed 53 jobs in a week.
- A PR run stops at its first failed job instead of running on, and package installs retry.
- Release builds are hermetic and use no CI caches; one release workflow builds every platform without a key ([#241](https://github.com/Elacity/elastos-runtime/pull/241), [#247](https://github.com/Elacity/elastos-runtime/pull/247), [#299](https://github.com/Elacity/elastos-runtime/pull/299)).

A full run now takes 50 to 80 minutes, up from 32 last week. Part of that is the new installed-Home journeys; part is that the shared compiler cache stores nothing, so every job compiles about 1,800 crates from scratch, as Irzhy found ([#310](https://github.com/Elacity/elastos-runtime/issues/310)). The macOS runners also vary by up to 24 minutes on the same steps. Fixing the cache is the next CI job. The merge queue stays off for now (decided 8 October, confirmed 9 October).

Checks before a push run on rented Linux machines (76 runs from 6 to 9 October, plus 55 that were turned away because another check was running), and pushes go through a queue that runs the pre-push gate one branch at a time (50 attempts, 36 passed). Real-machine tests use scripts that install a release on a fresh Linux machine or the Jetson and then run update, Undo, an interrupted update, low disk, or the AI journey (70 runs from 6 to 9 October).

## How we work (changed this week)

- One release, five goals in order, weekly signed test releases, and only two milestones: 0.8.0 and After 0.8.0 (7 October).
- After the first signed install, everything comes from inside ElastOS; only the release build fetches outside software, from checksum-pinned recipes ([#217](https://github.com/Elacity/elastos-runtime/issues/217)).
- Status lives in issue bodies, edited in place. state.md and TASKS.md were removed from the repository ([#239](https://github.com/Elacity/elastos-runtime/pull/239)), and five Browser issue bodies were rewritten on 8 October with the old text kept as comments.
- Each fix gets fast checks and a review by an AI from a different model family: Claude reviews Codex's work and Codex reviews the operator's. Each batch gets one full check and one CI run, and only failed jobs are rerun. Nobody should start CI by hand just to get build files; the Chat session did once, on 9 October.
- Lanes: the Codex release and update sessions stopped on 5 October. Local AI moved from Codex to the operator (OMP) on 8 October. Codex runs Browser and Chat under the operator's steering. The Codex Chat session now marks its GitHub comments as agent comments, because they post from Anders's account.
- When the shared Mac's disk dropped below 10 percent free and blocked builds, old release folders and finished worktrees were deleted; it now has more than 80 GB free.
