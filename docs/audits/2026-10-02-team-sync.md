# ElastOS weekly report, 26 September - 2 October 2026

v0.7.1 shipped on 30 September as developer builds, and the team moved to weekly releases on `develop`. On 1 October a security review found that ElastOS does not yet keep its core promise that a hacked Home or app reaches nothing else. We paused the public demo, wrote one plan to fix it ([#173](https://github.com/Elacity/elastos-runtime/issues/173)), and merged the first three fixes. CI is now about twice as fast. Last week's report: [19-25 September](https://github.com/Elacity/elastos-runtime/blob/docs/weekly-2026-09-25/docs/audits/2026-09-25-team-sync.md).

How we work changed on 2 October. A PR merges into `develop` when all checks are green and an independent review from a different AI model family than its author has passed; changes to the gateway, page security headers or frames must also pass the installed Home journey. Codex can request such a review itself (`elastos-pr-review`). Irzhy moves from reviewing every PR first to the isolation design, the threat model, the hacked-Home test suite and review after merge. `main`, tags and releases stay with Anders. Seven PRs merged overnight under this rule, and the project board now lists issues only.

User data is the newest gap. Device keys, wallet keys and the Recovery Kit key are plain files in the Runtime's data folder; the passkey protects sign-in, not those files. On a hosted Home such as the seed, the operator can read every account's wallet and private data. There are no real users or value on hosted accounts yet. [#209](https://github.com/Elacity/elastos-runtime/issues/209) plans the fix before that changes: keys in the OS keystore unlocked by the passkey ([#210](https://github.com/Elacity/elastos-runtime/issues/210)), the user's own client verifying signed code before it handles keys ([#211](https://github.com/Elacity/elastos-runtime/issues/211)), and a confidential VM checked by attestation ([#212](https://github.com/Elacity/elastos-runtime/issues/212)).

This week merged 25 PRs (the 0.7.1 release line, then `develop`) and completed 15 issues. 88 issues were created, many of them the isolation plan; 70 are open.

Decisions needed next: Irzhy's confirmation of his new role; the 0.7.2 scope on Wednesday, shipped on 7 October as developer builds; whether only two tracks (isolation and local AI) run until 0.8.0; where the new signing key is kept before the first signed release; and the hosted trust model for #209 before hosted accounts hold real value.
