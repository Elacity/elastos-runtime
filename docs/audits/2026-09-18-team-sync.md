# ElastOS 0.7.1: weekly team report

**Work completed after the 11 September report through 18 September 2026.** The previous checkpoint is [the 5 to 11 September report](https://github.com/Elacity/elastos-runtime/blob/093b51ca/docs/audits/2026-09-11-team-sync.md). This report separates source work, installed proof and public deployment so that progress in one area is not mistaken for release acceptance in another.

The strongest result this week is a signed SmolLM2 content capsule completing the intended local journey on a fresh isolated Apple silicon Home: signed install, catalogue discovery, Marketplace Get through Content and Carrier, two real Assistant replies, honest unknown Stop settlement, reload, full Runtime restart and reuse without another model transfer. The remote-service path also let a Linux seed Home use Qwen running on the Mac after the model owner approved access.

The signed 0.7.1 artifacts are now public. [The public Home](https://elastos.elacitylabs.com/home/) runs the matching Linux Runtime and preserved its existing account, identity, passkeys and source configuration. A fresh isolated Apple silicon Home installed from the public installer, discovered SmolLM2, completed Marketplace Get, produced two Assistant replies, and restored the same conversation and model after reload and a full Runtime restart. The public Home lists the same verified model, but its own Get currently fails at `MetadataRead` while the local content backend restarts. Remote Qwen from the Mac is also not restored on the public Home. These are preview blockers; the full release gates remain open.

## Model delivery evidence

The model work now covers three distinct operations that had previously been mixed together:

1. **Get the package.** Marketplace requests an exact signed content-capsule CID. Content and Carrier fetch, verify and atomically admit its complete closure.
2. **Keep it available.** A Home or storage-only holder retains the verified package without receiving inference authority.
3. **Use inference.** Assistant selects a compatible local provider or an approved remote service. That grant does not grant access to the consumer's storage, sandbox or tools.

The released source overlay is `a48ed2a7`, tree `04b3c271ab10`. Its built Apple silicon Runtime remains the tested `42e31e30`, tree `67de379c49a5`, with SHA-256 `82593dfc71f53cffa2dd5fd8c68cbaf4a048890929bf08a85aeb83354558c29f`. The released Linux Runtime has SHA-256 `63b3cdb06a45523f008fc4e67b50eb795a074890b0a3e839cba2ffa5d532d830`. SmolLM2 weights are 144,811,072 bytes with SHA-256 `c4a3dd037301b6ecea31d6da37f5cd793ead920dd5ddfe6d589294628d6ce66a`.

The installed journey passed two Assistant sends, preserved the conversation and selected model across Home reload and a full Runtime restart, and observed unchanged model bytes and completed-byte count during reuse. Stop returned `settlement_unknown`, which is the truthful backend result for that run.

The remaining distribution gap is now specific to the public seed path. A fresh Mac consumer found and admitted SmolLM2 through the public installation and normal trusted-source configuration. The public Home retains and lists the same CID, but its bounded metadata read uses a 100 ms offline request while the local content backend is restarting. Repair and prove that path, then prove fallback from a stale or unavailable holder without manual source editing.

## Remote inference evidence

Remote Qwen now uses the same Assistant model contract as local inference. The Mac Runtime owns the model, offer, grant and provider run. Carrier transports the operations. The seed owns its principal, conversation and draft.

Installed checks covered an approved request and reply, exact request identity, saved-chat recovery, replay without another dispatch, owner revoke, grant resume and a capacity refusal that starts no additional backend work. Restart during an unresolved run retained the consumer record and avoided redispatch. Unknown settlement remains visible instead of being rewritten as success.

The open release checks are the second-principal denial, final Busy and retry behavior on matching artifacts, public seed to Mac proof, and the combined model plus Browser service check. Remote Qwen remains Required for 0.7.1 under the current Notion decision.

## Browser position

Browser work made useful progress, but it is not ready for a release claim. The two required placements remain:

- Home, Browser UI, Engine and Exit on the Mac.
- Home and Exit on Linux, with the approved Engine on the Mac.

Recorded journeys cover ordinary navigation, typing, video, decoded audio and all 13 close effects. Profile state now has installed evidence in both placements. Local reload and controlled interruption recovery also have evidence. Repairs preserve the selected Engine and Exit, distinguish transfer and ingress failures, retain restore errors and measure inbound audio against the RTP clock.

The remaining blockers are concentrated rather than architectural. Remote reload still needs to complete within the accepted recovery gate. The audio path needs a stable result without the recorded queue gap. Wallet requests must return through Runtime and Carrier to the consumer's Wallet. File upload, failure UX, launch and input distributions, media quality, lifecycle endurance and final manual review remain open. The model publication work currently owns the shared test resources, so Browser is preserved and paused rather than repeatedly rerunning the same incomplete journey.

## Protected-content position

[PR62](https://github.com/Elacity/elastos-runtime/pull/62) now points to `9d623977`. Irzhy reports 1,780 `elastos-server`, 97 wallet-provider and 94 chain-provider tests passing, with formatting and strict Clippy clean.

The source now treats a creator's settled mint as the same kind of owned copy used for a purchase. A `.ddrm` capsule carries the metadata needed to identify authority, KID, token, ledger, content type and content CID. Mint, listing, availability, ownership and playback rights remain distinct states. A lapsed Wallet approval can be requested again, and the upfront entitlement check reads the chain head while irreversible key release still depends on finalized state.

The final J5 proof remains open. Acceptance now uses Base mainnet because the previous Anvil fork RPC could not return the mined transaction receipts needed by the journey. The live buy leg has not run on the current branch. Completed-mint adoption after restart and custody cleanup also need installed proof.

Live testing found a useful performance issue. Publishing a 689 KB file took about 46 seconds even though local storage and custody pins completed in milliseconds. About 44 seconds were spent joining a per-CID Carrier gossip topic through the public DHT path. Creator also labels this full wait as encryption although encryption finishes near the start. The plan now treats publish latency and truthful progress as part of the Required J5 journey.

The immediate work should stay narrow. The public goal is a truthful 0.7.1 Home with a signed model capsule that both a fresh Runtime and the seed can discover, acquire and use. Browser and protected content keep their full acceptance gates and remain separate from this model-delivery preview.
