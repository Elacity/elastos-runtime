# KNOWN_GAPS — Capsule Inspector

Build-visible registry of what the Inspector does **not** yet assert, so gaps are
impossible to forget and "we should fix this" becomes a tracked, enforceable
contract instead of prose. (Pattern from `LESSONS.md`: *turn an audit into a
build-visible gap registry, not a doc that rots*.)

Each **open** gap below has a `#[ignore]`d **ratchet test** that encodes the
desired end-state and **fails today** (hence ignored — non-blocking in a shared
tree). Closing a gap = wire the feature, delete the `#[ignore]`, the test goes
green, and the row moves to "Closed."

## Enforced invariants (the inverse — already guaranteed, not gaps)

These are *closed by construction* and worth recording so they aren't mistaken
for open work:

- **Merge gate-contract tripwire** — `carrier_bridge::tests::carrier_inspect_ops_match_canonical_action_contract` drives a real carrier call per inspect op at its canonical action; goes red the moment DDRM's `required_action_for` would fail-close an inspect op. Enforced now.
- **No secret/handle leakage (#16)** — `inspect_provider::tests::capsule_detail_renders_contract_without_leaking_authority` proves the raw signature / token never appear in output.
- **Two-tier scope, fail-closed (#11)** — `elastos-runtime::inspect` unit tests + `tests/inspect_conformance.rs` prove a SelfOnly caller cannot read another capsule.
- **Verified-signer projection (G2 core)** — `inspect_provider::tests::ratchet_provenance_verified_signer_present` runs a real ed25519 sign + verify (`verify_capsule_signer`) and asserts the projection fills `signed_by` with the matched-key fingerprint and reports `trust_level: "verified"` ONLY when a genuine check resolved a signer (honest-null / "signed" otherwise). The verifier resolving the matched key is enforced by `signature::verifier::tests::*`. Enforced now; live population over the serve path is tracked as G2b.
- **Observed granted capabilities (G1 core)** — `inspect_provider::tests::ratchet_granted_capabilities_populated` records a REAL `capability_grant` event in an `AuditLog` and proves `RuntimeAuditLogGrantSource` folds it into `granted_capabilities` (resource + action + granted) through the live op path, with a negative honest-empty case. Mirrors the runtime-side fold (`handler/request_handler.rs`) so the two agree. Observed / best-effort / unsigned per G8; never the manifest's requested capabilities (those stay in `required_capabilities`). Enforced now; live population over the serve path is tracked as G1b.
- **One canonical grant authorization path (G4a / Principle 10)** — the live capability mint is authorized only by the approval-gated HTTP handler routing through `approval::decide` (`api/handlers/capability.rs::grant_request`); the runtime IPC grant arm (`handle_grant_capability`) is neutralized to fail closed and mint nothing, proven by `test_runtime_grant_arm_fails_closed` (unit + integration) flipping from the old un-gated grant. The only `Some(true)` approver is an authenticated shell POST on an existing pending request; `decide` fails closed for any `None`/`Some(false)` source. `CapabilityManager::grant` (the signing primitive) is untouched, and `delegate` is a dormant test-only primitive with no request entry. *Recording* a signed approve/deny stays open as the G4 recording row (G4b), merge-coupled with G3 dispatch.
- **Audit fail-closed on the user-deny write (G8a)** — post-merge this rides dDRM's signed hash chain: `AuditLog::emit` writes durably (write + flush + fsync, per-record ed25519) and returns `Result`; `PendingRequestStore::deny_request` writes the `CapabilityDenied` record BEFORE the status mutation and aborts the denial (the request stays Pending) if the durable write fails, proven by `capability::pending::tests::deny_request_fails_closed_when_audit_write_fails` (a real read-only-fd I/O failure via the `with_file_handle` seam) with a happy companion that records into the chain. The high-frequency grant/use/revoke path keeps best-effort `emit_best_effort` (fail-open by design); routing those through the signed chain + verify-on-read remain open as G8b.
- **Domain-separated signatures are verifiable (G8b step 1)** — `crypto::domain_separated_verify` is the direct inverse of `domain_separated_sign` (recomputes `SHA256(domain || \0 || payload)` and checks the Ed25519 signature, fail-closed), enforced by `crypto::tests::domain_separated_verify_round_trips_and_fails_closed` (valid accepts; tampered / wrong-domain / wrong-key / malformed-hex all reject). The audit signing scheme can now be verified, not just produced. Remaining G8b: a verify-on-read caller (the inspector's attested/signed becomes cryptographically verified, not mere presence) and routing capability events through the signed plane.
- **Self-tier inspect route (Principle 16, fail-closed by construction)** — an app/browser principal can now reach `inspect/self` through the gateway and read ONLY its own capsule record. The gateway allow-lists `self` to the browser/app principal set (System ops stay pinned to System), injects the authenticated `principal_id` from the verified Home launch token, and the provider's `self` branch forces target = caller = that principal (NEVER `request["id"]`), routed through the canonical `inspect::authorize_view` / `InspectScope::SelfOnly` (caller == target). Proven end-to-end by `gateway_tests::inspect::inspect_self_returns_own_record_and_ignores_client_id` (own record + client-id ignored) and `inspect_self_token_cannot_reach_system_capsule_op` (allow-list blocks escalation). Out-of-scope / missing-principal return explicit errors (never silent-empty); the provider-level scope denial is unreachable post-injection, so gateway parity with the carrier transport's `inspect.out_of_scope` audit event is a low-priority follow-up.
- **Act leg: previewed gate == enforced gate, through a real executed dispatch (G3 core)** — `carrier_bridge::tests::carrier_rights_op_gate_enforces_exactly_the_previewed_action` drives the real rights op `has_access_by_content_id` end to end via an in-process provider: the action read out of an EXECUTED `plan` preview is exactly the action a token must carry to clear the carrier gate for that op and REACH the provider; a token one action off (Write) at the SAME matching resource is denied (`capability_denied`) BEFORE dispatch, so the denial is provably action-driven (exact-equality gate, no hierarchy). `carrier_bridge::tests::rights_fixture_preview_actions_match_verb_map` pins, for every op the shipped rights manifest declares, that the real `invoke::plan_provider_operation` action set equals `{required_action_for(op)}` — preview (manifest authority) and enforce (verb map) are disjoint tables with no shared function, so drift fails loudly. Only the ACTION dimension is pinned (the manifest's `elastos://rights/*` resource vs the per-op carrier resource diverge by construction); universal coverage across ALL provider ops + the `affordance.operation` path stay open as G3b.
- **Consent recording: signed, fail-closed, symmetric approve/deny (G4b)** — the human consent decision is now an attested ribbon entry on dDRM's signed chain on BOTH sides. Deny: `CapabilityDenied` via `deny_request` (emit + `?` before the status mutation, G8a). Approve: the new `AuditEvent::CapabilityApproved { request_id, session_id, resource, action, approver }` (the decision-level mirror of `CapabilityDenied`, keyed on request/session not the token) recorded by `PendingRequestStore::approve_request` fail-closed, called by the `grant_request` handler BEFORE the token mint and propagated — so an approval that cannot be durably+signed recorded mints no token, leaves the request Pending, and returns nothing. Earned by `capability::pending::tests::approve_request_fails_closed_when_audit_write_fails` (a real read-only-fd failure aborts) + `approve_request_records_signed_decision_that_verifies` (`verify_chain` accepts the ed25519 signature). The Home runtime ribbon renders the approval (`gateway_home_runtime`), and the approver (`session.owner | session.id`), previously discarded, is now captured. grant()'s best-effort `CapabilityGrant` stays as a non-authoritative token-issuance breadcrumb (no double-count).
- **The full five-beat loop turns once, end to end, on one signed chain** — `carrier_bridge::tests::five_beat_loop_turns_once_on_one_signed_chain_over_a_real_consent_token` composes the proven beats over the real rights op `has_access_by_content_id`: PLAN (executed inspect/plan derives the gate from the manifest), CONSENT (`request_capability` -> the real `grant_request` records a fail-closed signed `CapabilityApproved` before minting), ACT (that real minted token -- not hand-crafted -- clears the carrier gate and executes against an in-process rights mock, recording `CapabilityUse`), AUDIT (the in-memory ring holds the consent + act decisions AND `verify_chain` re-verifies every ed25519 signature on the on-disk log -- two surfaces asserted separately). `CapabilityState` + `BridgeContext` share ONE manager + pending store + signed chain, so the token validates on the same signing key the gate checks. A negative control proves the gate is enforcing and the denial is honestly attested as a failed `CapabilityUse` (success=false). Honest scope: only CONSENT is fail-closed (request/grant/use are best-effort, asserted by presence); the token validates because the capsule session carries its real identity (`session.vm_id`) and the carrier validates against the SAME field — post-flip (`cbc8929e`) this is the production identity path, not a test artifice.
- **Identity flip: one canonical `vm-{name}` through mint, validate, and inspector (G-ID CLOSED)** — `cbc8929e`: `grant_request` mints the token at the requester's `requester_capsule_id` (recorded from `session.vm_id`), fail-closed FORBIDDEN when absent (`capability::tests::grant_mints_at_requester_capsule_identity` + `grant_fails_closed_when_no_capsule_identity`); the three HTTP capability gates (`storage`/`namespace`/`provider`) validate against `session.vm_id`, denying on `None` (never a fallback to `session.id` or `""`); mint and validate read the SAME field, so they agree by construction for a `vm-{name}` capsule and fail closed symmetrically for `None`. The live bundled-viewer regression (`serve_web_capsule`'s app_session) is fixed by populating it with `vm-{manifest.name}`. The inspector folds grants under the normalized `vm-{name}`. The five-beat e2e now binds the carrier to `session.vm_id` (the prod path). Deploy with a clean restart (pre-flip session-id tokens drain). Remaining: G1b-LIVE granted-caps on serve (composite source) + WASM-carrier identity.

## How to use this file
- A new gap → add a row + an `#[ignore]`d ratchet test (or note "pending scaffold" if no API exists yet).
- Closing a gap → wire it, delete the `#[ignore]`, confirm the test is green, move the row to a "Closed" section (or delete it — this is memory, not an archive).
- A gap proven safe-by-construction → move it to "Enforced invariants" (confirming-safe is as important as finding-bad).
